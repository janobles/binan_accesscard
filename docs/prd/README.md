# Product requirements

Documents in this folder describe work that has not been built yet. Each one
states a problem, the constraints the solution has to respect, and the decisions
still open, so a brainstorming session can start from facts rather than from
memory.

A PRD is not a design. It says what has to be true when the work is done, not
which classes to write. When a PRD turns into an implementation, the design that
comes out of it belongs in `docs/superpowers/specs/`, and whatever ships gets
documented in the numbered handbook chapters. The PRD stays as it was written.
